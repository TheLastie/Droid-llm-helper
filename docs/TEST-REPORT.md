# Тест-отчёт OfflineRef

Дата: 2025-10-05 · Версия APK: 0.18.7+ · Проверка: автоматическая (CI) + песочница

## Метод

Перед каждой сборкой CI прогоняет два независимых гейта на **реальной базе, которая пойдёт в APK**:

1. **Smoke test** (`tools/smoke_test.py`) — структура базы: документы ≥15, фрагменты ≥500,
   метки страниц ≥300, страниц-картинок ≥100. Деградировавшая база не допускается к сборке.
2. **Self-test** (`tools/selftest.py`) — 5 слоёв функциональности (см. ниже).
   Провал критического слоя = красная сборка, APK не публикуется.

Дополнительно в песочнице отрисованы скриншоты всех экранов из живых данных
(`screen1_chat.png`, `screen2_kb.png`, `screen3_verbatim.png` в `/output`).

## QA-кейсы (слой 2)

Подосиновик, бледная поганка, мухомор, подберёзовик, парацетамол, обморок,
кровотечение из носа, кипячение воды, SOS, полярная звезда, перегрев двигателя,
прикуривание аккумулятора, запах газа, аварийный рюкзак, обморожение, медведь в тайге,
огонь без зажигалки, узел булинь, признаки инсульта, состав аптечки.

Покрытие: 10 тематических документов + грибной справочник (4 запроса).

## Визуальная верификация (песочница)

Отрисованы и просмотрены три экрана из реальных данных поиска:
- чат с источниками «(фрагмент N/M, стр. X)» и кнопкой страницы;
- экран базы знаний (19 документов, счётчики фрагментов);
- дословный режим `!мухомор` (3 фрагмента, мгновенно).

## Известные ограничения (не дефекты)

- Поиск не понимает перефразы («оказать помощь при обмороке» ≠ «потерял сознание») —
  планируется слой эмбеддингов v2.
- Англоязычный документ русским запросом не находится.
- L5 на CI-раннере медленнее порога; на устройстве скан SQLite быстрее на порядок.

## Как перепроверить

Локально: `python3 tools/selftest.py путь/к/kb_base.zip`
В CI: любой push в main прогоняет оба гейта; лог шага «Self-test» содержит JSON-отчёт.
